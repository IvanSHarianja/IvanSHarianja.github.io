MY-TRUCK — Sistem Operasional & Keuangan Alat Berat

Memindahkan penjualan material, sewa alat berat, kontrak armada, proyek borongan, dan laporan keuangan dari catatan Excel manual ke satu sistem untuk beberapa PT.

Laravel Filament Livewire Tailwind CSS MySQL Tahap UAT menjelang go-live
  • Hak akses per peran (Admin, Accountant, Owner) sehingga tiap peran hanya melihat transaksi dan laporan yang dibutuhkan
  • Multi-perusahaan: data tiap PT terpisah dalam satu aplikasi
  • Jurnal otomatis dari transaksi operasional (invoice, pembayaran, penjualan material)
  • Laporan neraca, laba rugi per lini usaha, arus kas, perubahan ekuitas, dan neraca saldo — dapat diekspor ke PDF
  • Persediaan material dengan harga pokok rata-rata bergerak (moving average)

Masalah

Penjualan material, sewa alat, kontrak armada, dan keuangan dicatat terpisah di Excel, sehingga sulit mengetahui laba tiap lini usaha dan posisi piutang secara cepat.

Peran saya

Menggali kebutuhan, merancang database dan hak akses, membangun seluruh modul, lalu menjalankan UAT bersama pengguna bisnis dan menyempurnakan fitur dari masukan mereka.

Tantangan teknis

  • Penomoran jurnal yang berhenti di 1.000 transaksi per PT per bulan — ditelusuri dan diperbaiki agar tanpa batas.
  • Pembatalan (void) transaksi harus merambat: jurnal pembelian yang dibatalkan ikut mengembalikan stok material.
  • Isolasi data antar PT pada query laporan, sekaligus mempercepat laporan dengan membatasi data yang dipindai.
  • Hak akses laporan yang ternyata belum dicek — ditemukan, diperbaiki, lalu modul lain disisir untuk pola serupa.

Kode sumber milik perusahaan. Tangkapan layar menggunakan data contoh.

Inoutlab — Sistem Alur Kerja Studio Interior

Mengelola seluruh alur kerja studio desain interior dalam satu aplikasi: calon klien → klien → proyek → RAB → tanda tangan online → invoice → kwitansi, dilengkapi landing page publik.

Laravel 12 Filament 5 Tailwind CSS 4 Alpine.js MySQL GitHub Actions

  • Dokumen siap cetak: RAB, SPK, invoice, dan kwitansi, dengan rencana pembayaran per termin
  • Deploy otomatis ke server production setiap kali kode di-push

Keputusan teknis

  • Uang disimpan sebagai rupiah bulat (integer), bukan desimal, agar tidak ada selisih pembulatan. Termin terakhir menyerap sisa pembagian sehingga total termin selalu sama dengan nilai kontrak.
  • Nomor dokumen dibuat dengan row lock, sehingga invoice atau kwitansi tidak bernomor ganda walau dua admin menyimpan bersamaan.
  • Otorisasi per objek: setiap halaman pratinjau dokumen dicek dengan policy, foto KTP klien disimpan di penyimpanan privat, dan HPP hanya terlihat oleh Super Admin.
  • Endpoint tanda tangan publik dibatasi (rate limit) untuk mencegah percobaan token secara massal.

SIPLAPOR — Aplikasi Pengaduan Masyarakat

Menggantikan pengaduan manual lewat surat dengan aplikasi web untuk memperbaiki komunikasi antara polisi dan masyarakat. Setiap laporan dapat dilacak dari pengiriman hingga hasil penyelidikan.

Laravel AdminLTE MySQL ICONIX
  • Kebutuhan digali langsung dari pemangku kepentingan kepolisian dan dimodelkan dengan proses ICONIX
  • Antarmuka terpisah untuk masyarakat dan petugas: Pengawas, Kapolrestabes, Divisi, dan Admin
  • Alur status: diverifikasi → diterima/ditolak → disposisi → diproses → selesai
  • Nomor laporan unik, unggah bukti, dan notifikasi di setiap perubahan status

Masalah

Pengaduan lewat surat sulit dilacak: masyarakat tidak tahu perkembangan laporannya, dan pimpinan sulit memantau laporan yang belum ditangani.

Solusi

Alur kerja digital sesuai proses di instansi: pengawas memverifikasi, Kapolrestabes mendisposisikan ke divisi berwenang, lalu divisi mencatat penyelidikan dan hasilnya. Akses tiap halaman dibatasi dengan middleware per peran.

Yang akan saya tingkatkan

Otorisasi per data (masyarakat hanya melihat laporannya sendiri, divisi hanya laporan yang didisposisikan kepadanya), penyimpanan bukti secara privat, dan log aktivitas — karena data pengaduan bersifat sensitif.
